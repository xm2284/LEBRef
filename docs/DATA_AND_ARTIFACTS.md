# Data and artifact policy

This repository accompanies the Pervasive and Mobile Computing submission of
LEBRef. It distributes code, locked protocols, and small released summary
results. It does not distribute raw datasets, feature caches, or trained
checkpoints.

## Datasets

Use the official dataset sources and licenses for:

- SmartFallMM
- UMAFall

The manuscript cites the dataset sources in its data section. Historical or
preliminary datasets such as SisFall, WEDA, and KFall are not part of the
current main paper experiments and should not be committed.

## External artifacts

The following files should be provided through GitHub Releases, Hugging Face, or another artifact host, with SHA256 checksums:

- `UniMTS.pth`
- WEDA-derived checkpoint(s) used for frozen feature extraction
- GATE2A code directory (`wedafa_common` and supporting modules)
- locked V6 reference outputs (`v6_results` + `v6_legacy_results`)
- optional V9 trained heads
- optional V9 result directory
- optional frozen feature caches

### GATE2A code directory (required by the V6 feature-cache builder)

Role: `src/core/legacy_smartfallmm.py::configure_imports` imports this
directory before building the frozen WEDA representation, and `build_model`
calls `wedafa_common.build_model_from_checkpoint(...)`. Without it, the V6
runner (and therefore V9 / V19) cannot load the frozen encoder.

Acquisition: the GATE2A code is derived from the WEDA project's gate-2a
training/evaluation code (see the WEDA paper and its official source). It is
not bundled in this repository. The author must publish a tarball containing
`wedafa_common.py` plus the modules it imports, or the exact upstream
repository/commit and the small glue module needed.

Expected path after download: `artifacts/gate2a_code/` (must contain
`wedafa_common.py`). Point `GATE2A_CODE_DIR` (`.env`) at it.

Checksum placeholder: publish a `sha256` for the tarball on the artifact host
and record it here after the author's release. Until then the manifest entry
is intentionally empty (no silently-assumed artifact).

### Locked V6 reference outputs

`artifacts/v6_results/` is the output directory of the locked V6 pipeline
(`esra_ablation/...` and `locked_alarm_duty_audit/...`); it is required by
`run_experiment_v9.py --v6-results-dir` for the standard-head and esra-full
comparisons. `artifacts/v6_legacy_results/{smartfallmm,umafall}/` holds the
locked V6 legacy reference records (`fivefold_results.json` plus
`fold*/seed*/result.json` and `best_head.pth`); it is required by
`resolve_args` in `src/core/v6_run_experiment.py`. Both can be regenerated by
running the locked V6 pipeline, or downloaded from the artifact host.

Recommended local placement after download:

```text
artifacts/
  UniMTS-main/
  gate2a_code/                      # wedafa_common.py + imported modules
  checkpoints/
    UniMTS.pth
    weda_fold0_acc_seed0_best_model.pth
  feature_cache/
    smartfallmm/
    umafall/
  v6_results/                       # locked V6 esra_ablation + locked_alarm_duty_audit
  v6_legacy_results/
    smartfallmm/
    umafall/
  v9_results/
```

## Do not commit

- raw datasets
- `.pth`, `.pt`, `.ckpt`, `.joblib`
- `.npy`, `.npz`, `.pkl` feature/probability caches
- local logs
- advisor comments or private manuscript notes
